# Лабораторна робота № 6

**Тема:** Створення форми авторизації та реєстрації користувачів на PHP з використанням MySQL.

**Мета:** Ознайомитися з інтеграцією PHP та MySQL, навчитися працювати з базою даних для зберігання та обробки даних, забезпечити безпечне зберігання паролів за допомогою хешування.

---

## 1. Структура проєкту

| Файл | Призначення |
|------|-------------|
| `dump.sql` | Дамп бази даних `users_db` (таблиця `users`) |
| `config.php` | Підключення до MySQL, запуск сесії, допоміжні функції |
| `register.php` | Форма та обробка реєстрації |
| `login.php` | Форма та обробка авторизації |
| `welcome.php` | Захищена сторінка (доступна лише після входу) |
| `logout.php` | Завершення сесії |
| `index.php` | Перенаправлення на сторінку входу |
| `style.css` | Стилі |

## 2. Підготовка бази даних

Створено базу `users_db` і таблицю `users`:

```sql
CREATE TABLE users (
  id INT NOT NULL AUTO_INCREMENT PRIMARY KEY,
  username VARCHAR(50) NOT NULL UNIQUE,
  email VARCHAR(100) NOT NULL UNIQUE,
  password VARCHAR(255) NOT NULL
);
```

Імпорт: `mysql -u root -p < dump.sql` або через phpMyAdmin (вкладка «Імпорт»).

## 3. Запуск

1. Встановити XAMPP / OpenServer (Apache + PHP + MySQL).
2. Скопіювати файли в `htdocs/lab6/`.
3. Імпортувати `dump.sql`.
4. За потреби змінити дані підключення у `config.php`.
5. Відкрити `http://localhost/lab6/register.php`.

## 4. Реалізація

### Реєстрація (`register.php`)
- HTML-форма з полями username, email, password, метод **POST**.
- Серверна валідація: непорожнє ім'я, коректний email (`filter_var`), пароль від 6 символів.
- Пароль хешується, дані записуються через **prepared statement** (`INSERT ... VALUES (?, ?, ?)`).
- Дублікати username/email ловляться за кодом помилки MySQL `1062` (UNIQUE).

### Авторизація (`login.php`)
- Форма з полями username і password.
- Користувач шукається через prepared statement (`SELECT ... WHERE username = ?`).
- Пароль перевіряється функцією `password_verify()`.
- При успіху: `session_regenerate_id(true)`, запис у `$_SESSION['user_id']` та `$_SESSION['username']`, перенаправлення на `welcome.php`.

### Захищена сторінка (`welcome.php`)
Перевіряє наявність `$_SESSION['user_id']`; якщо його немає — перенаправляє на `login.php`.

### Вихід (`logout.php`)
Очищає масив `$_SESSION`, видаляє cookie сесії та знищує сесію.

## 5. Хешування паролів: `md5()` та `password_verify()`

Завдання вимагає одночасно `md5()` для хешування та `password_verify()` для перевірки. Напряму вони несумісні: `password_verify()` розпізнає лише хеші у форматі `password_hash()` (bcrypt/argon2), тому порівняння з «чистим» md5-хешем завжди дає `false`.

Тому використано поєднання:

```php
// реєстрація
$hash = password_hash(md5($password), PASSWORD_DEFAULT);

// авторизація
password_verify(md5($password), $hash);
```

Так виконуються обидві вимоги, а в базі зберігається bcrypt-хеш із випадковою «сіллю».

**Важливо:** сам по собі `md5()` вважається небезпечним для паролів (швидкий, вразливий до rainbow-таблиць і колізій). У реальних проєктах слід використовувати лише `password_hash($password, PASSWORD_DEFAULT)` без `md5()`.

## 6. Заходи безпеки

- **Prepared statements** (`mysqli::prepare`, `bind_param`) — захист від SQL-ін'єкцій.
- **Хешування паролів** — у БД немає відкритих паролів.
- **`htmlspecialchars`** (функція `e()`) — захист від XSS.
- **`session_regenerate_id(true)`** — захист від фіксації сесії.
- **UNIQUE-індекси** на `username` та `email`.
- Однакове повідомлення про помилку для неправильного логіна й пароля (не розкриває, чи існує користувач).

## 7. Тестування

| Сценарій | Очікуваний результат |
|----------|---------------------|
| Реєстрація з коректними даними | Повідомлення про успіх, запис у БД |
| Реєстрація з існуючим username/email | Повідомлення про дублікат |
| Вхід з правильними даними | Перенаправлення на `welcome.php` |
| Вхід з неправильним паролем | Повідомлення про помилку |
| Відкриття `welcome.php` без входу | Перенаправлення на `login.php` |
| Натискання «Вийти» | Сесія знищена, перехід на `login.php` |
| Ввід `' OR '1'='1` у поле логіна | Вхід не відбувається (SQL-ін'єкція неможлива) |

У ході роботи реалізовано реєстрацію та авторизацію користувачів на PHP з MySQL. Освоєно роботу з `mysqli` та підготовленими запитами, сесіями `$_SESSION`, хешуванням паролів і перевіркою через `password_verify()`.
